# es-419 terminology proposal for the remaining candidate strings

**Status:** AI-authored proposal for independent challenge; no catalog changes or review status changes. Scope is the 157 `unreviewed` es-419 candidate keys left after correction batches 001–012 in the full-review worktree. Existing catalog text is inconsistent, so this policy should be applied as a group before any of those keys is marked reviewed.

## Contract boundary

Translate prose and presentation labels, including diagnostics. Preserve exact placeholders (`{token}`, `{command}`), CLI switches, metavariables, VFP commands/property identifiers, file formats and paths, SQL/code identifiers, JSON keys, enum/id values, and literal outputs whose bytes are parsed. The call site matters more than the English appearance of a key. For example, `studio_builder_registry_for_catalog` obtains localized `.title`, `.description`, and `.vfp9_equivalent_display`, while `.id`, `.entry_point`, and `.vfp9_equivalent` stay literal (`src/studio/builder_registry.cpp:52–101, 137–190`). `studio_builder_kind_name` returns fixed `builder`/`wizard` (`:105–112`), and the host writes that fixed kind into JSON (`apps/copperfin_studio_host/studio_host_main_builder.cpp:402`). Do not translate those machine fields through catalog changes.

The toolbox host has separate JSON field names (`contextCount`, `dryRun`, `mutatesAsset`, etc.) and a text renderer that explicitly calls `catalog.translate` for `StudioHost.ToolboxPalette.Text.Label.*` (`apps/copperfin_studio_host/studio_host_main_toolbox_palette.cpp:414–445, 450–528`). This is evidence that these ten remaining labels are intended to be localized **in text mode**; the JSON names must stay byte exact. Because text output may be scraped externally, verify text-mode compatibility tests and document its locale dependence before changing them.

## Review sequence

1. Independently challenge the glossary above, especially `Builder`, `dispatch`, `TabStop`, and text-label contract assumptions. Resolve one term across its entire family rather than accepting isolated accent edits.
2. Classify each remaining key by actual call site as prose, display label, text-mode label, or protected literal. Proposal batches should include exact current source/translation/proposal hashes and preserve placeholders and machine tokens.
3. Add focused locale tests for text and JSON host output, Builder title/ID separation, OLE/TabStop diagnostics, and Rushmore rationale. Perform UI inspection for clipping and meaning; AI linguistic review carries uncertainty and is not equivalent to qualified human or in-product validation.
