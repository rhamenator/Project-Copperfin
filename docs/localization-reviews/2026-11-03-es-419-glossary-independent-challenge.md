# Independent review: es-419 terminology proposal

**Reviewed:** `docs/localization-reviews/2026-11-03-es-419-glossary-proposal-draft.md` against current Copperfin source and es-419 catalog, 2026-11-03. **Decision:** adopt the Builder and machine-field boundary; revise the dispatch/admission, text-label, VFP keyboard-property, and debugger policies before using this glossary to approve the remaining keys. This is AI text and code review only; it does not certify native-speaker suitability or rendered UI behavior. No repository files were changed.

| Area | Verdict | Evidence and required adjustment |
|---|---|---|
| Builder vs wizard | **Accept with scope check** | `src/studio/builder_registry.cpp:105–112, 137–150` returns invariant `builder`/`wizard` kinds and keeps `.id`, `.entry_point`, and `.vfp9_equivalent` literal while drawing `.title`, `.description`, and `.vfp9_equivalent_display` from localized text. **Builder** is a defensible VFP workflow noun; **asistente** fits wizard. Replace reviewed/display `Constructores` only after matching the complete Builder UI family. Do not touch IDs, JSON kinds, or `builder.app`. |
| Dispatch and admission | **Revise wording policy** | `src/studio/builder_dispatch.cpp:60–112` distinguishes admission, a dispatch plan, `dry_run`, and executed state, so this distinction must survive translation. But **despacho** and especially **admisión de invocación** are literal and may read as shipping or institutional admission. Choose a user-facing family through a few full diagnostic examples, such as *autorización para iniciar* and *autorización para ejecutar*, before converting dozens of keys. The code treats `dry_run` as a Boolean here; the diagnostic phrase “non-dry-run” is prose, whereas `--dry-run` and JSON `dryRun` are exact tokens. Do not keep English `dry-run` in every prose message merely because a field of that name exists. |
| Text-mode toolbox labels | **Revise; do not assume snake_case contract** | `apps/copperfin_studio_host/studio_host_main_toolbox_palette.cpp:450–528` intentionally calls `catalog.translate` for text labels, while the JSON writer above it emits invariant `contextCount`, `dryRun`, etc. `tests/test_studio_host_json_parse_diagnostics_toolbox_palette.inl:60–84` explicitly expects pseudo-localized text labels and no raw `toolbox_context:` under qps-ploc. Thus neither English bytes nor underscore shape is a guaranteed invariant of text mode. The ten remaining labels should be reviewed as one family, but choose natural Spanish labels (with accents if appropriate) or document a separately supported parseable text format. Changing existing `ruta_activo` to `ruta_recurso` without a compatibility decision offers little value and may break external text scrapers; JSON is the stable parsing surface. Verify text and JSON output in at least en-US, es-419, and pseudo-locality. |
| OLE drop labels | **Revise presentation rule** | `src/vfp/visual_asset_editor_property_setters_appearance.cpp:88–110` passes fixed `OLEDropMode`/`OLEDropEffects` property names separately from localized labels. Concise labels such as **modo de soltar con OLE** and **efectos al soltar con OLE** are reasonable. Appending `(OLEDropMode)` to every short diagnostic label is unnecessary, may produce very long output, and is not a meaningful “first mention” rule for reused catalog strings. Preserve the API identifier in code, CLI syntax, or a diagnostic that specifically needs to name it. |
| TabStop and KeyPreview | **Revise; source meaning is narrower** | The setter writes literal `TABSTOP` with `.T.`/`.F.` (`src/vfp/visual_asset_editor_property_setters_behavior.cpp:62–107`). The underlying UI property controls whether Tab can focus a control, not insertion of a tab character; **permite tabulación** could mislead. Prefer **recibe el foco con Tab** or **accesible con Tab** after checking label width. `KeyPreview` means the form receives key events before the active control, so **vista previa de teclas** suggests a keyboard preview. Prefer **captura previa de teclas** or a short explanatory phrase. These meanings align with [Microsoft's TabStop](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.control.tabstop) and [KeyPreview](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.form.keypreview) control documentation; applying them to VFP is an inference that should be checked against VFP UI context. |
| Rushmore match reasons | **Accept with wording check** | `src/runtime/index_seek_optimizer.cpp:577–639` assigns localized `match_reason` strings using score thresholds (high ≥90, moderate ≥60, possible >0), while execution strategy remains an enum. Keep **Rushmore**, `AND`, and command names. Use **coincidencia de Rushmore de confianza alta/moderada** and **posible coincidencia de Rushmore** consistently; “confianza” describes the heuristic score, not a measured probability. Run locale-specific optimizer tests if these display strings change, and document that consumers should not parse localized rationale text. |
| Debugger terminology | **Revise for existing catalog consistency** | The glossary's **ventanas de inspección** conflicts with already AI-reviewed `AssetEditor.Debugger.Tab.Watches = "Expresiones vigiladas"` and `AssetEditor.Debugger.EvaluatingWatchStatus = "Evaluando expresión vigilada..."` in the current es-419 catalog. Use **ventanas de expresiones vigiladas** in subsystem prose and **expresión vigilada** in watch errors, or deliberately revise the whole debugger family with new exact-hash evidence. **Puntos de interrupción** already matches the catalog. |

## Suggested release-gate checks

1. Approve a complete family-level glossary with example sentences for Builder, dispatch/admission, keyboard properties, and watch expressions before marking isolated strings reviewed.
2. Keep exact-hash evidence for each final source/translation pair; do not transfer approval from an earlier draft after wording changes.
3. Run focused localized CLI/JSON tests and pseudo-locality layout checks. This text review leaves runtime behavior and clipping unverified.
