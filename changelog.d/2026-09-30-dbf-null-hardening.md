- 2026-09-30: Hardened `REPLACE ... WITH .NULL.` so the previous value does not stay recoverable. An inline value (`C N F D T L I B Y V Q`) was already blanked in the `.dbf` record (now pinned by tests). Memo, General, Picture and Blob fields: nulling now sets the field's `_NullFlags` bit (earlier builds ignored the null request for memo fields) and nulling, overwriting or `ADDITIVE`-appending zero-fills the superseded block in the `.fpt` unless another record still references it; Blob (`W`) fields, which the DBF layer previously treated as opaque bytes, now reclaim their FPT block too. Set `COPPERFIN_DBF_MEMO_SCRUB=0` to keep VFP9's leave-in-place behavior. The command-`UNDO` and transaction backup files, which held a whole-table pre-image with the superseded value and were never wiped or deleted at session end, are now overwritten and removed on commit, rollback, `UNDO` and session end. The working buffers and table-buffering caches that held the old value are cleared with a non-elidable `secure_clear` (best-effort). Remaining exposures are listed in `docs/80-dbf-nullflags-field-format-notes.md`.
