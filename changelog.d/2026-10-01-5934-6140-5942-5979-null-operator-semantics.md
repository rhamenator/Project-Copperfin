- 2026-10-01: Fixed #5934, #6140, #5942 and #5979: NULL now propagates the way installed VFP9 does. Comparison and arithmetic operators return NULL when an operand is NULL (`.NULL. = .NULL.`, `.NULL. + 1`, `'a' + .NULL.` and so on are NULL, not a definite value or an error), `AND`/`OR`/`NOT` are three-valued (`.NULL. AND .F.` is `.F.`, `.NULL. OR .T.` is `.T.`), `BETWEEN()` and `INLIST()` follow three-valued rules, `EMPTY(.NULL.)` and `ISBLANK(.NULL.)` are `.F.`, `NVL()` substitutes only for NULL and `EVL(.NULL., x)` is NULL, and a NULL condition in `IF`, `IIF`, `FOR` or `WHERE` acts as false. On a nullable table, `COUNT FOR NAME = 'x'` and `COUNT FOR NAME <> 'x'` no longer count the NULL row. A program that relied on NULL comparing equal to zero or blank now sees NULL, as in VFP9; guard with `ISNULL()` or `NVL()`. Built-in function propagation (#5936), operator type strictness (#5939, #5940) and the typed null for `VARTYPE(x, .T.)` (#6506) are separate.
