- 2026-09-30: Fixed #6511 and #6591: `APPEND FROM ... TYPE CSV` now discards the first CSV line unconditionally, as installed VFP9 does (verified byte-for-byte on `09.00.0000.7423`), instead of only when it matched the target field names in order. A mismatched, reordered, UTF-8 BOM-prefixed (including quoted, LF-only and CR-only), or blank first line, and a `FIELDS` subset with a reordered header, no longer import the header as a data row; a file with no header loses its first data row, exactly as VFP9 does. The rule is shared by local tables and SQL/result cursors. `APPEND FROM` for CSV/DELIMITED/TAB now also sets `_TALLY` to the number of records appended, as VFP9 does (SDF, which VFP9 also tallies, is unchanged here); `TYPE DELIMITED` parsing is otherwise unchanged. The field-name matching helper is removed. A quoted header containing a line break and the VFP9 error for an empty file are intentionally left unspecified.
