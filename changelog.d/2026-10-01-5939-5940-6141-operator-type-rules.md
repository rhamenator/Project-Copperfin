- 2026-10-01: Fixed #5940 and #6141 and the expression part of #5939: operators now reject operand types VFP9 rejects, with VFP9's error numbers, instead of coercing silently. `1 + 'a'`, `'a' - 1`, `'a' = 1`, `.T. + 1` and mixed-type comparisons raise error 107; `'a' * 2` and `2 / 'a'` raise 9; `2 ^ 'a'`, `-'a'`, `'a' $ 1`, `1 AND 2` and a non-Logical `IIF` or `ICASE` condition raise 11; `NOT 1` raises 9; `BETWEEN` with mixed types raises 107. `.F. AND 1` and `.T. OR 1` still return `.F.` and `.T.` as VFP9 does, and NULL still propagates. Errors are catchable with `TRY/CATCH` and visible to `ERROR()`. A program that relied on the lenient behavior now sees the error VFP9 would raise; note that a `PUBLIC` variable starts as `.F.`, so `n = n + 1` needs `n = 0` first. Statement conditions (`IF`, `DO WHILE`, SQL `WHERE`) and Currency typing follow separately.
