- 2026-09-30: Fixed #6583, #6585, #6586 and #6587: `COPY FILE` and `RENAME` now follow installed VFP9 for their operands. An unquoted, unparenthesized token is a literal filename (a parenthesized name expression or function call is still evaluated), and `*`/`?` in the source filename expand case-insensitively to every matching file, each mapped into the destination: `COPY FILE *.bin TO *.bak` copies `one.bin` to `one.bak`, `?ne.bin TO ?ne.bak` maps the `?`, a directory destination receives the copies, and a fixed destination is overwritten by each copy in turn (`RENAME` onto a fixed destination fails on the second match, as VFP9's error 7 does). A missing source or a pattern that matches nothing is an error, as in VFP9. VFP9's lower-casing of bare names and its `.dbf` default for an extensionless bare `RENAME` name are not replicated.
