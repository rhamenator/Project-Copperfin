- 2026-09-30: Fixed #6499: a task cancelled while blocked in an explicit `FLOCK()` or `RLOCK()` retry no longer treats the cancellation as ordinary lock contention. The cancelled lock attempt now faults the running statement, so the task ends with an error pause (`CFTASKSTATUS` reports `error`) instead of `.F.` and a normal completion, and a cancel is observed even when the scheduler only yields between retry attempts. The cancellation bookkeeping (transaction rollback and the `runtime.task.cancelled` event) is unchanged, no lock ownership is recorded for the cancelled attempt, ordinary contention and timeouts still return `.F.`, and implicit locks keep their cancelled message. The regression test that documented the old behavior now requires the halted outcome, and an `RLOCK()` variant is added.
