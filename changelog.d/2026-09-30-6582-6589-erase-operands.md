- 2026-09-30: Fixed #6582 and #6589: `ERASE` (and its synonym `DELETE FILE`) now follows installed VFP9 for its operand. An unquoted, unparenthesized token is a literal filename (`ERASE cF` erases the file named `cF`, `ERASE (cF)` evaluates the variable), quoted strings, parenthesized name expressions and function calls are still evaluated, and `*`/`?` in the filename expand case-insensitively to every matching file, whether the wildcard is bare, quoted or returned by a UDF; a pattern or file that matches nothing is silent. `DELETE FILE <name>` used to be parsed as a record `DELETE` and never worked; it now erases the file. `COPY FILE` and `RENAME` are not changed here.
